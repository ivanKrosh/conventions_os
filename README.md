# Домовленості програмування для ОС — демонстрації

Демонстраційні програми до заняття 4 курсу «Системне програмування»
(ВСП «Фаховий коледж інформаційних систем і технологій КНЕУ ім. Вадима Гетьмана»).

Тема заняття — **домовленості, за якими прикладна програма взаємодіє з Windows API**: те, чого не перевіряє компілятор, але без чого програма працює неправильно.

## Склад рішення

Рішення `Demo_Lecture_4.slnx`, шість проєктів — по одному на кожну домовленість.

| Проєкт | Файл | Що показує |
|---|---|---|
| `Demo0_types` | `types.c` | типи Windows як `typedef`: розміри `BYTE`…`WCHAR`; чому `BOOL` — це `int` і чому порівняння `if (result == TRUE)` є помилкою |
| `Demo1_text` | `text.c` | пара функцій A/W; `strlen` проти `wcslen` проти `sizeof` для одного й того самого рядка; вивід через `WriteConsoleW` |
| `Demo3_handlers` | `handllers.c` | дескриптор як дозвіл, який треба повернути: два режими роботи, з `CloseHandle` і без нього, з підрахунком дескрипторів процесу |
| `Demo4_error` | `error.c` | ланцюжок `перевірка результату → GetLastError → FormatMessage` і втрата коду помилки, якщо його прочитати не одразу |
| `Demo5_buffer` | `buffer.c` | двофазний виклик `GetCurrentDirectoryW`: хто виділяє буфер, що повертає функція в кожному з трьох випадків; поле `cb` структури |
| `Demo6_exit` | `exit.c` | код повернення процесу (`ERRORLEVEL`) і розділення `stdout` та `stderr` |

## Як відкрити у Visual Studio

**Що має бути встановлено.** Visual Studio (Community достатньо) з компонентом **«Розробка класичних застосунків на C++»** (Desktop development with C++). Якщо його немає — запустіть Visual Studio Installer, натисніть *Modify* і позначте цей компонент.

**Крок 1. Відкрити рішення.** Двічі клацнути `Demo_Lecture_4.slnx` або у Visual Studio: *File → Open → Project/Solution* і вибрати цей файл. У Solution Explorer з'являться шість проєктів.

> Файл рішення збережено в новому форматі `.slnx`. Його відкривають свіжі версії Visual Studio; якщо ваша версія повідомляє, що формат невідомий, оновіть Visual Studio або відкрийте потрібний проєкт напряму — *File → Open → Project/Solution* і вибрати `.vcxproj` у теці демонстрації.

**Крок 2. Перевірити конфігурацію.** На панелі зверху мають стояти **Debug** і **x64**. Саме на x64 дескриптор має розмір 8 байтів — на x86 демонстрація типів покаже інші числа.

**Крок 3. Вибрати проєкт для запуску.** У рішенні шість окремих програм, тому Visual Studio треба сказати, яку саме запускати: у Solution Explorer клацнути правою кнопкою на потрібному проєкті → **Set as Startup Project**. Назва активного проєкту виділяється жирним.

**Крок 4. Зібрати.** *Build → Build Solution* (Ctrl+Shift+B) — зберуться всі шість проєктів.

**Крок 5. Запустити — обов'язково Ctrl+F5.** Комбінація **Ctrl+F5** (*Start Without Debugging*) залишає вікно консолі відкритим після завершення програми. Якщо натиснути F5, програма відпрацює й вікно миттєво закриється — ви нічого не встигнете прочитати.

**Крок 6. Передати аргументи командного рядка.** Демонстрації 3, 1 і 6 приймають аргументи (`leak`, `gui`, код завершення). У Visual Studio їх задають так: правою кнопкою на проєкті → *Properties* → **Configuration Properties → Debugging → Command Arguments** → ввести значення (наприклад, `leak`) → *OK*. Переконайтеся, що зверху у вікні властивостей вибрано ту саму конфігурацію — **Debug** і **x64**.

**Якщо в консолі нечитні символи.** Це не помилка збирання, а кодова сторінка вікна консолі — див. розділ «Як запускати» нижче.

**Не вимикайте прапорець `/utf-8`.** Він заданий у властивостях кожного проєкту (*C/C++ → Command Line → Additional Options*) і потрібен тому, що вихідні файли збережено в UTF-8 без BOM. Без цього прапорця компілятор читає їх у системній кодовій сторінці, і кожен байт кириличного тексту стає окремим символом у широких літералах: демонстрація 1 покаже `wcslen` = 22 замість 12, а `sizeof` = 46 замість 26 — тобто саме той результат, який вона має спростувати.

## Як зібрати з командного рядка

**Командний рядок** (Developer Command Prompt for VS), кожен файл окремо:

```
cl /utf-8 /W4 types.c
cl /utf-8 /W4 text.c user32.lib
cl /utf-8 /W4 handllers.c
cl /utf-8 /W4 error.c
cl /utf-8 /W4 buffer.c
cl /utf-8 /W4 exit.c
```

Прапорець `/utf-8` обов'язковий: вихідні файли збережено в UTF-8, і без нього кириличні рядки буде зіпсовано вже на етапі компіляції.

## Як запускати

```
Demo3_handlers.exe          дескриптори закриваються
Demo3_handlers.exe leak     CloseHandle навмисно пропущено
Demo1_text.exe gui          додатково показує MessageBoxW
Demo6_exit.exe 2            завершується з кодом 2
```

Після `Demo6_exit.exe` подивитися код завершення: `echo %ERRORLEVEL%`.

Якщо замість українського тексту в консолі видно нечитні символи — перемкніть кодову сторінку командою `chcp 65001`. Це і є одна з домовленостей, про які йдеться в занятті: кодування задає не програма, а середовище відображення.
